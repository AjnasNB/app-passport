Connected records, verified context, useful AI

Arkiv Graph is a graph SDK and AI-context layer on Arkiv's indexed entities. AI Passport is the reference application that uses it with Qarinah context and a real hosted model.

The system in one view

1. Original evidence and Qarinah context

Public source documents and synthetic coding fixtures provide the demo evidence. Qarinah compiles selected cited events and source identities. Its full private store remains local. This public application sends only selected public or synthetic context to hosted inference.

The copied Qarinah baseline and its Apache-2.0 notices are disclosed. Original Qarinah project folders and commits remain unchanged.

2. Graph records on Arkiv

Each node, edge and manifest is a separately signed readonly entity. Typed indexes include namespace, schema_version, graph_hash, kind, node_id, node_type, from_id, to_id and relation. The generic profile accepts domain-specific node and relationship names.

The generic namespace is arkiv-graph-v1. The reference application's historical ai-passport-graph-v1 signing domain stays compatible through an adapter. New revisions have new root digests. Content-addressed source paths preserve the exact code behind historical revisions.

3. Complete graph verification

The reader queries live entities for a pinned root, then verifies EIP-191 signatures, accepted issuer wallets and creator agreement. One current accepted manifest must list every node and edge digest. Duplicate keys, ambiguous members, dangling edges, extra members, wrong roots and expired records fail verification.

The reconstructed graph must match the pinned canonical SHA-256 root. Traversal is a bounded directed breadth-first search in the SDK. The protocol does not claim native Cypher, server-side recursive joins or production-scale graph performance.

4. Graph AI-context adapter

readGraphContext verifies the complete graph before selecting a connected path. Truncated paths fail. A caller-controlled loader can supply original source bytes, which must match the signed node digest before a labelled excerpt enters the packet. The SDK never fetches arbitrary source URLs or opens files on its own.

The packet carries the graph root, block, selected nodes and relationships, source references, verification flags and its own digest. It declares contentRole: untrusted-data and execution_authority: false. A source reference without loaded bytes is explicitly unverified.

The public /api/context reader allows three predefined context paths and four fixed source files. It accepts no arbitrary URL, provider, upload or filesystem path. Character budgets cap output; token estimates are labelled approximate.

5. AI Passport admission

A graph signature establishes identity and attribution. AI Passport separately checks the current accepted context and runtime reviews, same-author targeted withdrawals, expiry and current source snapshot. Failed evidence blocks the model call. Readers choose their accepted issuers and reviewers.

Both demo roles are project-controlled wallets. They do not represent independent organizations, upstream endorsement or a universal safety certificate.

6. Useful tools and hosted inference

The actual model is Cloudflare-hosted Meta Llama 3.2 3B. It receives a compact selected context and a fixed task. Generated release guards use a finite interpreted specification and pass six boundary tests before display. Arbitrary generated JavaScript is never executed.

India number learning calculates exact integer paise and Indian grouping deterministically. Rounded lakh/crore ratios are labelled display values. UPI Safety Quest uses deterministic scoring and project-authored NPCI reference questions. Optional AI commentary cannot replace verified numeric results.

7. Output validation and receipts

Successful receipts bind the reported context, runtime, graph root, source digests, read blocks, model alias and output. A receipt is project-generated evidence of the reported run, not a proof of hosted model computation. Visitor receipts stay in the browser unless downloaded. Only selected public or synthetic evaluation runs are anchored.

8. Independent SDK, CLI and MCP

An installed consumer can query the same graph through its own Arkiv RPC without this website backend, wallet or project access key. The CLI verifies and traces graphs and exports graph context. The stdio MCP server exposes trace_graph and read_context, both with explicit budgets and untrusted result roles.

The fresh consumer evaluation installs actual release tarballs, exercises both protocol profiles and checks success and incomplete-path boundaries. Reader configuration explicitly pins a root and accepted authors; automatic latest-root discovery is future work.

Why Arkiv matters here

Different applications can independently retrieve the same attributable, indexed connected records. Arkiv Graph provides a common manifest and context contract over that shared state. A conventional database remains sufficient for a single operator's private application. Graph structure alone does not require a blockchain.
