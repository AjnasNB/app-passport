One useful task, end to end

  1. Choose the coding handoffGenerate and test a release guard in the live reference app.
  2. Inspect AI inputsOpen the journey to see checked sources, graph root, selected events and the exact model evidence message.
  3. Check the outcomeThe generated guard must pass six interpreted boundary cases. Download its run receipt and model evidence.
  4. Withdraw the required reviewSelect the published withdrawn-review fixture. The next request stops before inference.

The evidence-message byte digest and complete receipt digest are checked in the browser. A self-consistent receipt does not establish that the provider executed specific weights or returned a truthful answer.

Reproduce without our application API

The clean consumer installs both public SDK tarballs, reads Tiramisu directly, verifies the generic and AI profiles, then runs actual CLI and stdio MCP checks. It does not call this website’s dynamic API or require a signing wallet.

git clone https://github.com/AjnasNB/arkiv-graph.git
cd arkiv-graph
npm ci --ignore-scripts
npm run build
npm run typecheck
npm test
node scripts/consume-graph-infra.mjs

Public RPC quota or transport failure can stop a live read. Use your own provider quota where needed. Never substitute an old positive result when the current read is unavailable.

Why this shared record layer?

The intended user is a builder handing reviewed AI context between independently operated clients. Clients can read attributable, indexed, expiring graph records through their own Arkiv provider and choose accepted authors. The signed manifest makes incomplete membership of a pinned revision detectable.

Operator database / API

A good fit for one private operator. Another consumer depends on that operator’s publication, availability and query service, unless a shared signed interchange is added.

Content-addressed file storage

Useful for source bodies and immutable bundles. Creator-indexed discovery, typed relationship queries and current review lifecycle require another service or convention.

Arkiv + this SDK

Uses Arkiv’s public indexed entities and creator metadata, with a documented graph contract, complete manifests and independent bounded readers.

These properties can be engineered on other stacks. Arkiv supplies a shared substrate here; this project does not prove that graphs are impossible in Postgres or that only Arkiv can provide attribution. Arithmetic and model inference do not require a blockchain.

Evidence and practical limits

Local test cases and scopeHosted browser resultsReal model/admission evaluationsFilm QA and credits
  • Signatures bind accepted authorship and content, not factual truth. Chain metadata and query completeness rely on the RPC provider; no independent state-proof verification is implemented.
  • The graph is bounded to 200 nodes, 500 edges, eight query pages and traversal depth eight. No production-scale benchmark or outside customer adoption is claimed.
  • Public source fixtures are used. Private memory, credentials and personal information stay off Arkiv. Receipts are project-generated reports; hosted model weights and computation are not attested.
  • Storage and signed validity expire. Renewal is an operator responsibility. Creation transactions, evaluation snapshots and the video preserve historical evidence.
  • Qarinah’s existing compiler and validator are disclosed reuse. The new graph contract, SDK, adapters and reference application are the challenge integration.
