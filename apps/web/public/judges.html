npm install @ajnasnb/arkiv-graph@0.3.0 @ajnasnb/ai-passport@0.5.0 qarinah@0.7.0

Repeat the three writes

Fund two dedicated Tiramisu wallets with free testnet GLM. Set TWO_CLIENT_PRODUCER_KEY and TWO_CLIENT_REVIEWER_KEY in your local process, or use the existing private operator helper with files outside the repository. Optional settings are TWO_CLIENT_RPC and TWO_CLIENT_API_KEY. No custom contract deployment is required.

npx tsx scripts/two-client-demo.ts --plan
npx tsx scripts/two-client-demo.ts --publish --hold-before-withdrawal

The CLI creates a unique session descriptor, publishes its passport and review, runs A and B, then saves the accepted-phase public report before waiting for Enter. The operator can inspect that phase before resuming. Enter publishes the review withdrawal; a separate bounded visibility check precedes B’s next fresh task request. All task receipts and visibility attempts remain inspectable. Unknown broadcasts retain signed intent and any known transaction hash in a local journal and are not automatically retried.

Only the operator CLI publishes. Public endpoints only read evidence; they provide no wallet signing, unauthenticated writer or private-context upload.

Generic infrastructure

AI reference application

27 nodes · 43 edges

71 signed entities in the compatible AI profile, including four selected historical AI run receipts. Visitor runs are not automatically published.

Reference graph entity evidence

Arkiv supplies indexed entities, original creator metadata, readonly creation, expiry and transactions. The SDK adds graph conventions, complete signed manifests and bounded directed traversal. Query-time creator allowlists precede pagination; signatures and issuer/creator agreement are checked locally. The graph is reconstructed and verified before selecting the coding context path and its source.

A single operator can use an ordinary database. The benefit here is shared attributable evidence that compatible readers can query through their own provider. Traversal is SDK code, not native Cypher or Solidity. Both publishers are project-controlled; no external adoption or official endorsement is claimed.

Keep evidence scopes separate

  • Local tests: the release suite passed 198 tests. These include adversarial signatures, exact-target withdrawal coverage, creator filtering, admission deadlines and runtime-source binding. Local inference orchestration uses mocks.
  • Browser evidence: eighteen checks comprise sixteen existing flows and two additional UI regressions using generated signed fixtures and mocked responses. They are not eighteen independent live-network tests. The actual two-client browser capture has its own report: four requests, zero browser errors.
  • Hosted AI: the coding handoff, India number tutor and safety coach have a separate real-provider evaluation. Inspect AI inputs shows the exact evidence message. Hosted weights and provider computation are not attested. The two-client flow uses no inference.
  • Local performance: synthetic 20-, 100- and 200-node CPU measurements exclude network, RPC, storage and gas. At 20 nodes, indexed traversal showed no improvement (0.1148 versus 0.1144 ms median). At 200 nodes/500 edges, indexed and scan medians were 1.0701 and 1.5017 ms. Complete signature/manifest/root verification was measured separately at 285.5, 1687.3 and 2843.6 ms. These are not production service or distributed-scale results.
  • Trust and lifetime: signatures bind accepted authorship and content, not truth. RPC metadata and query completeness remain trusted; no independent state proof is checked. Storage and signed validity expire. A withdrawal must cover both its target’s signed validity and storage expiry. Historical receipts never substitute for a current read.
